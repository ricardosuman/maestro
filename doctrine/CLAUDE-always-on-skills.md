# Always-on skills

- At the first coding task of every session — writing, reviewing, refactoring or designing code, or writing a spec for a lane — load `ponytail:ponytail` (default intensity) and `andrej-karpathy-skills:karpathy-guidelines` with the Skill tool, and apply both for the rest of the session. Do not wait to be asked.
- They govern the architect's own output too: specs, verdicts on lane reports and reviews, and any code the architect types. Lanes don't load skills, so the doctrine already pastes the ponytail block into every spec; carry the karpathy guidelines into specs the same way — surgical changes only, assumptions surfaced, verifiable success criteria.
